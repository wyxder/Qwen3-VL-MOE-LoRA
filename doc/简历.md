# 📄 简历项目经历 · Qwen3-VL-MoeLORA 多模态微调与本地 RAG 多智能体助手

> 说明：以下内容基于仓库代码与训练日志整理，所有数字均来自 `README.md` 的实测记录或源码常量。项目为**个人独立完成的工程实践**，非线上商业系统，因此不包含用户量、并发、营收类指标；场景与收益均如实描述，未做夸大。

---

## 🧭 一句话简介

基于 Qwen3-VL-4B-Instruct 在单卡 8GB 显存下完成 LoRA / MoT-LoRA / MoE-LoRA / IA3 四种参数高效微调对比，并打通 COCO 数据流水线、SwanLab 训练可视化、本地混合检索 RAG 与 PyQt5 多智能体问答桌面端。

**技术栈**：`Python + PyTorch + Transformers + PEFT + bitsandbytes + qwen-vl-utils + LangChain + FAISS + BM25 + Sentence-Transformers + ModelScope + SwanLab + PyQt5`

**目标业务场景**：面向「数据不出内网」的图文知识库问答场景——企业手册 / 技术文档 / 论文资料的本地化检索问答，以及个人学习资料的图文助手。要求模型权重、向量库、会话记录全部留在本地，不使用任何云端 API。

## ⭐ 工作内容与 10 个亮点（STAR）

### 亮点 1 · 从零搭建可复现的多模态数据流水线

- **S**：COCO 2014 Caption 原始数据为图文混合结构，无法直接被 Qwen3-VL 的对话模板消费。
- **T**：在有限存储与算力下，产出一份「小体量、可复现、格式合规」的微调数据集。
- **A**：用 ModelScope SDK 拉取数据并限流到 500 条，逐条落盘 `image_id.jpg` 并写入 `image_path + caption` 的 CSV；再按 Qwen3-VL 的 `<|vision_start|>…<|vision_end|>` 协议组装成 `conversations` 结构的 JSON。
- **R**：3 个脚本串成完整链路（下载 → CSV → JSON），最终得到 **496 条训练样本 + 4 条留出样本**，单样本序列上限 **8192 token**，重跑一次即可复现全部数据。

### 亮点 2 · 8GB 显存下跑通 4.44B 多模态模型微调

- **S**：基座 Qwen3-VL-4B-Instruct 全量参数 **4,443,714,048**，单卡 8GB 显存无法承载全参训练。
- **T**：在不换硬件的前提下让训练可跑、可复现。
- **A**：组合 `4-bit NF4 双量化（compute_dtype=fp16）` + `gradient_checkpointing` + `enable_input_require_grads` + 单专家小秩（r=8 / alpha=16）+ `batch=1 / 梯度累积 8`。
- **R**：LoRA 可训练参数 **5,898,240，占比 0.1327%**，5 epoch、**310 steps** 完整跑完，单卡可复现。

### 亮点 3 · 标准 LoRA 基线：文本 + 视觉双通道注入

- **S**：纯文本 LoRA 只适配语言侧，图文任务缺少视觉侧对齐能力。
- **T**：在保持参数效率的同时覆盖视觉模块。
- **A**：`target_modules` 同时纳入文本 `q/k/v/o_proj` 与视觉 `visual_q_proj / visual_k_proj`，共 **6 类模块**；`PeftModel.from_pretrained` 直接挂载 checkpoint 推理。
- **R**：训练全程平均 `train_loss = 1.5232`，耗时 **5666.18s（≈94.4 min）**，样本吞吐 **0.438 samples/s**，作为后续三种方案的对照基线。

### 亮点 4 · 自研 MoE-LoRA 层：多专家门控路由

- **S**：单一 LoRA 子空间对不同输入模式的适配能力有限。
- **T**：在 PEFT 框架内实现「多专家 + 动态选择」，且不引入辅助损失。
- **A**：继承 `LoraLayer` 自定义 `MOELoraLayer`——每层 **2 个独立 LoRA 专家**，`gate = Linear(out_features → num_experts)` 做 `softmax` 门控，`top-k(k=1)` 稀疏激活，`gate_dropout=0.1` 抑制门控过拟合，输出 `base + Σ(mask × expert × weight) × scaling`。
- **R**：可训练参数 **10,298,240（0.245%）**，平均 `train_loss 1.4217`，相比 LoRA 基线降低 **约 6.7%**；耗时 7802.80s，比基线增加约 37.7%，即「**用 +37.7% 训练时间换 -6.7% loss**」，选型结论有据可依。

### 亮点 5 · 自研 MoT-LoRA：Token 维度混合增强

- **S**：长序列图文上下文中，Token 之间的关联未被适配器显式建模。
- **T**：在 LoRA 增量上增加跨 Token 特征融合，且不破坏初始等价性。
- **A**：在 LoRA `A→B` 后接 `Conv1d(kernel=3, padding=1)` 做序列维混合，覆盖 3D/2D/其他三种张量形状；`adapter_B` 与 `token_mixer` 均零初始化，训练起点与原始模型严格等价；`mix_dropout=0.05`。
- **R**：实现可直接被 `get_mot_peft_model` 注入 PEFT，与其余方案共用同一套 5 epoch / 310 steps / lr=1e-4 训练配置，形成可横向对比的第三组实验（该组未单独留存 loss 日志，不做数字结论）。

### 亮点 6 · IA3 Adapter 对比实验与选型结论

- **S**：需要验证「更轻量的缩放式适配」在本任务上是否优于 LoRA。
- **T**：补齐第三类 PEFT 方案，形成完整横向对比。
- **A**：`IA3Config` 覆盖 **14 个 target_modules**（含视觉侧 `visual_q/k/v/o/up/down/gate_proj`）并指定 **6 个 feedforward 模块**。
- **R**：可训练参数 **7,340,928（0.165%）**，训练最快 **5347.34s（≈89.1 min）**、吞吐最高 **0.464 samples/s**，但平均 loss **1.9296**，比 LoRA 基线高约 **26.7%**——结论：**参数量最小 ≠ 效果最优**，本任务应优先 MoE-LoRA。

### 亮点 7 · 训练全流程可观测与自动评测推理

- **S**：多组实验超参相近，缺少可视化会导致结论不可追溯。
- **T**：让 3 组以上实验的每一步 loss、吞吐、预测结果都可回看。
- **A**：接入 `SwanLabCallback` 记录 project / experiment / 超参与指标；训练结束后用 `glob + os.path.getctime` 自动选取**最新 checkpoint**，构造测试 prompt 推理，并将图文预测结果 `swanlab.log({"Prediction": ...})` 上传。
- **R**：LoRA / MoE-LoRA / IA3 三组实验均留存 step 级日志（310 steps × 3），可对比 loss 曲线、梯度范数与吞吐；推理侧免去手工指定 checkpoint。

### 亮点 8 · BM25 + FAISS 混合检索 RAG，并做逐级降级

- **S**：单一向量检索对专有名词、编号类查询召回不稳定；且本地环境依赖不一定齐全。
- **T**：构建「召回率与准确率兼顾、缺依赖也不崩」的检索层。
- **A**：多编码（utf-8/utf-16/gbk/gb2312/latin-1）加载 `.txt/.md/.mdx/.csv/.log/.pdf`；`chunk_size=600 / overlap=80` 递归分块；BM25 与 FAISS **0.4 : 0.6** 加权融合（各取 Top-8 候选），再由 `BAAI/bge-reranker-base` Cross-Encoder 精排取 Top-4，最终返回 **Top-3** 片段。
- **R**：单文件缺失不影响启动——`rank-bm25` 缺失自动降级为纯向量检索，`sentence-transformers` 缺失自动跳过精排并打印提示，检索链路 **3 层降级**均可运行。

### 亮点 9 · 5-Agent 编排与 Reviewer 质检闭环

- **S**：单次 RAG 生成容易出现「答非所问 / 遗漏要点」，且过程不可解释。
- **T**：把一次生成拆成可解释的多步协作，并加入质量闸门。
- **A**：设计 `Planner`（拆 3-5 步计划）→ `Knowledge`（检索）→ `Manager`（判断是否用知识库 + 额外提示）→ `Responder`（多模态生成，支持接收反馈重写）→ `Reviewer`（输出 `Verdict: PASS/RETRY` + 具体建议）的串行编排；`Reviewer` 最多触发 **1 次**重写，避免无限循环。
- **R**：UI 可同时展示「调度建议 + 任务计划 + Reviewer 结论」与「RAG 检索证据」；实测归档记录中出现 1 次 `Verdict: RETRY` 并成功产出修订版答案，验证闭环生效。

### 亮点 10 · MCP 风格工具 + PyQt5 桌面交付

- **S**：用户需要把一次完整问答（问题、计划、证据、回答）沉淀成可存档文件，手工复制不可行。
- **T**：提供「一句话触发归档」的工具能力，并把整条链路做成可交互桌面端。
- **A**：用 LangChain `@tool("save_session_summary")` 封装归档工具，文件名做时间戳 + 中文 slug 化（正则清洗非法字符）；命中「总结对话 / 保存记录 / 归档 / summary / archive」等关键词时自动注入历史对话并落盘 Markdown；前端用 PyQt5 + `QThread` 异步推理，支持图片上传/大图预览、`max_new_tokens` 32–1024、`temperature` 0.1–1.2 可调。
- **R**：已产出 **2 份**会话归档 Markdown（含调度计划与检索证据），回答中回显文件路径；交付 **3 套**可运行界面（纯 FAISS / LangChain Runnable 链 / 5-Agent），单次推理不阻塞 UI。

1. 搭建 COCO Caption → CSV → Qwen3-VL 对话 JSON 数据流水线，产出 496 条训练样本，单样本 8192 token 上限，3 个脚本可复现。

8. 构建 BM25(0.4) + FAISS(0.6) 混合检索 RAG：600/80 分块、Top-8 召回 + bge-reranker-base 精排 Top-4、最终 Top-3，并对缺失依赖实现 3 层自动降级。
9. 设计 Planner/Knowledge/Manager/Responder/Reviewer 5-Agent 串行编排，Reviewer 以 PASS/RETRY 质检并最多触发 1 次重写，UI 同步展示计划与检索证据。
10. 基于 LangChain `@tool` 实现 MCP 风格会话归档（关键词触发、时间戳落盘），并用 PyQt5 + QThread 交付 3 套非阻塞桌面界面，图片与生成参数可调。

## 🧩 专题拆解（结合本项目的真实实现）

> 只写项目中确实存在的能力；未实现的模块在末尾单独说明，不作包装。

### 1️⃣ 多模态 AI

- **S**：任务输入是「图片 + 文本」，纯文本模型无法处理，且本地显存受限。
- **T**：让视觉与语言在同一序列中完成理解与生成。
- **A**：`AutoProcessor.apply_chat_template` 统一图文对话模板，`qwen_vl_utils.process_vision_info` 产出 `pixel_values / image_grid_thw`；训练时固定 `resized_height/width = 280` 平衡显存与细节；推理同时支持本地路径与 HTTP(S) URL。
- **R**：图文样本可稳定编码进 8192 token；LoRA 与 MoE-LoRA 两套权重均可直接挂载推理；桌面端支持 png/jpg/jpeg/bmp/webp 五种格式上传与预览。

### 2️⃣ RAG（检索增强生成）

- **S**：模型参数只有 4B，且企业/个人文档不在预训练语料中，直接问答易幻觉。
- **T**：用本地知识库把答案锚定在可追溯的文档片段。
- **A**：`RecursiveCharacterTextSplitter(600/80)` 分块 → `all-MiniLM-L6-v2` 向量化 → FAISS 检索 + BM25 关键词检索 → 加权融合 → `bge-reranker-base` 交叉编码精排 → 拼装 `[Doc n / source]` 上下文。
- **R**：支持 5 类文本扩展名 + PDF（共 6 种格式）；检索结果带来源与序号，可在 UI 侧栏逐条展示；三种缺失依赖场景（BM25 / CrossEncoder / 知识库为空）均能降级运行而不中断。

### 3️⃣ Agent（智能体）

- **S**：直接让模型「一步到答案」，复杂问题缺少中间推理与工具意识。
- **T**：把回答过程拆成「规划 → 调度 → 生成」的可解释步骤。
- **A**：`LocalQwenTextLLM` 复用同一份本地权重做纯文本推理（不额外占显存）；Planner 强制输出编号步骤并提示是否需要知识库；Manager 对「问题 + 检索摘要（截断 1200 字）」输出工具使用建议与额外提示。
- **R**：UI 中可见完整计划文本与调度建议；同一模型实例通过单例复用，避免重复加载 4B 权重。

### 4️⃣ 多智能体（Multi-Agent）

- **S**：单 Agent 无自检机制，答案完整性不可控。
- **T**：引入角色分工与质量闸门，且控制成本。
- **A**：5 个角色（Planner / Knowledge / Manager / Responder / Reviewer）由 `MultiAgentOrchestrator` 串行调度；Reviewer 解析 `Verdict` 行判定 PASS/RETRY，不通过则携带 `Feedback` 回传给 Responder；重写上限 1 次。
- **R**：一次问答最多 **2 次生成 + 2 次质检**，成本可控；实测归档中确认发生 1 次 RETRY 并输出修订答案；`AgentOutput` 统一返回 `plan / answer / supporting_documents / summary_path`，便于 UI 与后续接口复用。

### 5️⃣ MCP（Model Context Protocol）

- **S**：会话归档是明确的「工具型」动作，不该混在生成文本里。
- **T**：以工具调用方式把归档能力从对话逻辑中解耦。
- **A**：在 `tools.py` 中使用 LangChain `@tool("save_session_summary")` 定义工具（参数 `content / title`），`slugify` 清洗中文与非法字符，`REPORT_DIR` 自动创建；`MultiAgentOrchestrator` 通过关键词路由触发，并调用同步封装 `save_session_summary_sync`。
- **R**：已生成 2 份 `output/reports/YYYYMMDD-HHMMSS_总结对话.md`，回答末尾回显绝对路径，可直接归档复盘。
- **⚠️ 如实标注**：这是**「MCP 风格」的本地工具封装**，**不是**标准 MCP Server（未实现 JSON-RPC 协议与资源/提示词暴露），简历中应写「MCP 风格工具调用」，不宜写「实现 MCP Server」。

### 6️⃣ 评测与评估

- **S**：没有公开 benchmark，也缺少标注测试集，无法直接用 BLEU/ROUGE 证明效果。
- **T**：在现有条件下建立「可复现、可对比」的最小评估闭环。
- **A**：① 训练侧用 SwanLab 记录 step 级 loss、梯度范数、吞吐并横向对比 3 种 PEFT 方案；② 生成侧用 Reviewer 规则（PASS/RETRY + Feedback）做在线自检；③ 留出末 4 条样本做人工抽查，训练后自动加载最新 checkpoint 生成预测图并回传 SwanLab。
- **R**：3 组方案在**同数据、同超参**下完成对比，得出 loss / 时长 / 吞吐三维结论（MoE-LoRA 最优 loss，IA3 最快，LoRA 基线居中）；**尚未实现** BLEU/ROUGE 与 LLM-as-a-Judge 自动打分，已列入 Roadmap，简历中不应声称具备该能力。

### 7️⃣ Skills（未覆盖）

本项目**未实现** Skills 体系（无技能注册、技能路由、技能描述文件），仅有单一 `save_session_summary` 工具。为避免夸大，不单列该专题。
